# Technical Plan: Fix Issues 38, 39, and 40

## Problem Statement & Context
This plan addresses three high-priority issues from the review finding set (#37):

1. **Issue #38 (Review Finding #1)**: `fix(notifications): reminders fire at 09:00 UTC instead of device-local 9 AM`
   - Reminders in `lib/data/notifications/notification_scheduler.dart` use `tz.TZDateTime.local(...)`, but `tz.setLocalLocation` was never called, causing reminders to fire at 09:00 UTC (e.g. 5:00 AM EDT) instead of local civil time.
2. **Issue #39 (Review Finding #3)**: `fix(sync): restore failure falls through to first-run profile creation on bound account`
   - When a bind-time pull fails on an empty-but-bound database, `lib/ui/profiles/profile_home_gate.dart` falls through `SyncPhase.error` to `needsFirstRun` and renders `FirstRunScreen` (the create-profile form), risking data fragmentation on devices restoring an existing account.
3. **Issue #40 (Review Finding #5)**: `fix(schema): tags CHECK accepts non-string elements causing client decode deadlock`
   - The Postgres `tags` CHECK constraint and `sync_push` RPC validated array-ness and maximum length (<= 32), but did not validate that elements are strings. Non-string elements cause Dart's `row_codec.dart` to throw `RowCodecError(invalidTags)`, wedging the client sync pull cursor in an unrecoverable retry deadlock.

## Technical Design & Implementation Units

### Unit 1 (U1): Issue #38 — Local Timezone Notification Scheduling & Seam Injection
- **Dependency**: Add `flutter_timezone: ^5.1.0` to `pubspec.yaml` to resolve the host device's canonical IANA timezone.
- **Pure Calculation Helper**:
  Add `calculateReminderFireAt` in `lib/data/notifications/notification_scheduler.dart`:
  ```dart
  tz.TZDateTime calculateReminderFireAt({
    required LocalDate fireOn,
    required tz.Location location,
    int hour = 9,
  }) {
    return tz.TZDateTime(
      location,
      fireOn.year,
      fireOn.month,
      fireOn.day,
      hour,
    );
  }
  ```
- **Seam & Timezone Resolution**:
  In `FlutterLocalNotificationsScheduler`:
  - Accept optional `LocalTimeZoneProvider? localTimeZoneProvider` (`Future<String> Function()`) and `tz.Location Function()? locationProvider`.
  - In `initialize()`: call `tzdata.initializeTimeZones()` if locations are empty, resolve timezone via provider (defaulting to `FlutterTimezone.getLocalTimezone()` with fallback to `'UTC'`), and call `tz.setLocalLocation(tz.getLocation(tzName))`.
  - In `rescheduleAll`: compute `fireAt` using `calculateReminderFireAt` with `_locationProvider?.call() ?? tz.local`.
- **Verification**:
  - Add `test/data/notification_scheduler_test.dart` with unit tests verifying:
    - 9:00 AM local civil wall-clock calculation across time zones (`America/New_York`, `America/Los_Angeles`, `Asia/Tokyo`, `Australia/Sydney`) producing correct UTC instants.
    - Timezone provider error handling and fallback to UTC.
    - Integration with `resolveCurrentTimeZone()` from `lib/domain/util/timezone.dart`.

### Unit 2 (U2): Issue #39 — Restore Error Screen on Empty-but-Bound Account
- **New UI Screen**:
  Create `lib/ui/account/restore_error_screen.dart` (`RestoreErrorScreen`):
  - Key: `ValueKey('restore-error')`.
  - Display informative copy: `"Couldn't restore your account data. Check your connection and tap Retry."`.
  - Explicit action button: `FilledButton` with key `ValueKey('restore-retry-button')` labeled `"Retry"`, which invokes the provided `VoidCallback onRetry`.
- **Gate Logic in `ProfileHomeGate`**:
  Update `lib/ui/profiles/profile_home_gate.dart`:
  - Add helper:
    ```dart
    Widget? _restoreFailedScreen(
        SyncStatusController? sync, ProfileController controller, AuthController? auth) {
      if (sync == null) return null;
      final isBound = sync.snapshot.boundUserId != null || (auth != null && auth.currentUser != null);
      if (isBound && controller.needsFirstRun && sync.phase == SyncPhase.error) {
        return RestoreErrorScreen(
          onRetry: () => sync.requestSync(),
        );
      }
      return null;
    }
    ```
  - In `build()`:
    ```dart
    return _recoveryScreen(auth, gate) ??
        _syncPhaseScreen(sync) ??
        _restoreFailedScreen(sync, controller, auth) ??
        _profileScreen(controller);
    ```
- **Update `FirstRunScreen`**:
  In `lib/ui/profiles/first_run_screen.dart`:
  - Ensure that when `sync?.snapshot.boundUserId != null && sync?.phase == SyncPhase.error`, `FirstRunScreen` does not present a blank profile creation form.
- **Verification**:
  - Add widget tests in `test/ui/account_test.dart` and `test/ui/first_run_test.dart` asserting:
    - When database is empty, account is bound, and sync enters `SyncPhase.error`, `RestoreErrorScreen` is rendered.
    - Tapping the Retry button triggers `sync.requestSync()`.
    - Fresh un-bound install still displays `FirstRunScreen`.

### Unit 3 (U3): Issue #40 — String-Only Tags Constraint & Pull Quarantine Resilience
- **Database Schema Migration**:
  Create `supabase/migrations/20260903170000_tags_string_array_check.sql`:
  - Define immutable validation function:
    ```sql
    create or replace function public.is_valid_tags_array(p_tags jsonb)
    returns boolean
    language sql
    immutable
    parallel safe
    as $$
      select jsonb_typeof(p_tags) = 'array'
         and jsonb_array_length(p_tags) <= 32
         and not exists (
           select 1
             from jsonb_array_elements(p_tags) elem
            where jsonb_typeof(elem) <> 'string'
         );
    $$;
    ```
  - Update check constraint on `public.day_entries`:
    ```sql
    alter table public.day_entries
      drop constraint if exists day_entries_tags_check,
      add constraint day_entries_tags_check
        check (public.is_valid_tags_array(tags));
    ```
  - Update `public.sync_push` RPC to check `public.is_valid_tags_array(v_tags)` and reject non-string elements.
- **pgTAP Tests**:
  Update `supabase/tests/sync_push_test.sql` to verify rejection of non-string tags:
  - `sync_push` rejects `'tags', '[1, 2]'::jsonb`.
  - Direct insert to `day_entries` with `'[true]'::jsonb` throws check constraint violation.
- **Client Resilience**:
  - In `lib/data/sync/remote_rows.dart`:
    Add `QuarantinedRemoteRow` extending `RemoteRow`:
    ```dart
    final class QuarantinedRemoteRow extends RemoteRow {
      const QuarantinedRemoteRow({
        required this.id,
        required this.table,
        required this.serverVersion,
        required this.reason,
      });
      @override
      final String id;
      @override
      final SyncTable table;
      @override
      final int serverVersion;
      final String reason;
      @override
      DateTime get updatedAt => DateTime.fromMillisecondsSinceEpoch(0, isUtc: true);
      @override
      DateTime? get deletedAt => null;
    }
    ```
  - In `lib/data/sync/supabase_sync_transport.dart`:
    In `pullPage`, catch `RowCodecError` per row and construct `QuarantinedRemoteRow` carrying the row's `server_version`.
  - In `lib/data/db/storage.dart`:
    In `applyRemotePage` and `applyRemoteRows`:
    Ignore `QuarantinedRemoteRow` for database inserts, while `applyRemotePage` still writes `newCursor` to `sync_state`.
- **Verification**:
  - Add unit tests in `test/data/supabase_sync_transport_test.dart` and `test/data/storage_sync_test.dart` proving that a malformed row is quarantined and the sync cursor advances past it rather than deadlocking.
