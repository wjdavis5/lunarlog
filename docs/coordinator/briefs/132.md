## Settled decisions (do not re-litigate)

1. **Exclusion list is device-local, per profile, for v1** (roadmap KTD2). Store it in the existing device-local key-value store (`app_settings` via `LunarLogStorage.setSetting`/`DriftSettingsStore`, e.g. key `omittedCycles.<profileId>` holding a JSON list of cycle-start dates). Multi-device divergence is an accepted limitation — surface it in the UI (one caption line) rather than hiding it. Do NOT add it to the sync model.
2. **Vocabulary: cycle-only.** No fertility/ovulation wording in the new surfaces (this stands regardless of the PRIVACY.md amendment in flight via #142 — the history feature needs no such vocabulary).
3. Spread/confidence thresholds are provisional constants, named and commented as such.

## Architecture constraints (repo law — read AGENTS.md first)

- `lib/domain` is pure Dart (no Flutter imports) — the confidence mapping, history-list derivation, and exclusion-aware averaging belong there (extend `lib/domain/prediction/prediction.dart` and/or `lib/domain/episodes/episodes.dart`; `Episode` from episodes.dart is the raw material and currently never reaches the UI).
- UI goes under `lib/ui/` (new files, e.g. a history section/screen) and reads through repositories/providers only — no direct `lib/data` imports from new UI files beyond what existing UI files already do (check `lib/app.dart` provider wiring and follow it).
- Pure recompute per stream emission; no persisted derived state (matches the prediction service's shape).
- Estimate disclaimer appears on every surface showing a number.
