# Task brief — Issue #114: guardian_invitations.token_hash is table-readable

Issue: https://github.com/wjdavis5/lunarlog/issues/114

## Issue body (summary)

`token_hash` on `guardian_invitations` is readable via the table's SELECT grant + RLS (guardians of a profile can read its invitation rows), and possession of the hash alone is sufficient to redeem an invitation (`accept_guardian_invitation(p_token_hash)` compares the client-supplied hash directly). Any guardian who can read a pending invitation row can redeem it before the intended recipient. Fix so that reading the table never yields a redeemable credential.
